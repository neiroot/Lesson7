# AI-анализатор видеовстреч

Локальное приложение для русскоязычных встреч. Принимает MP4 и WebM без ограничения по длительности, хранит расшифровку и конспект в SQLite и даёт уточнить имена спикеров. Размер загрузки настраивается через `MAX_VIDEO_MIB` и по умолчанию ограничен 500 МиБ. Назначить имя для встречи можно без регистрации голоса.

Длинные записи обрабатываются по частям. Приложение сопоставляет метки спикеров по общим участкам речи на стыке частей. При недостатке совпадений один голос может получить несколько меток.

В AI-конспекте краткий обзор расположен отдельно от вкладок «Принятые решения», «Задачи» и «Открытые вопросы». Каждый пункт раскрывает ссылки на исходные реплики. Кнопка «Обновить конспект» пересобирает результат из сохранённой расшифровки.

## Импорт из Яндекс Диска

В интерфейсе можно вставить публичную HTTPS-ссылку Яндекс Диска на один MP4/WebM-файл. OAuth для такого импорта не нужен. Ссылки других сервисов и произвольные URL не принимаются.

Для автоимпорта из папки нужно один раз создать OAuth-приложение на [oauth.yandex.ru](https://oauth.yandex.ru/):

1. Выберите тип «Веб-сервисы».
2. Добавьте Redirect URI `http://127.0.0.1:8000/api/integrations/yandex/callback`.
3. Выдайте только право «Чтение всего Диска» (`cloud_api:disk.read`).
4. Скопируйте Client ID в `.env`; Client Secret не нужен, так как приложение использует PKCE.

```dotenv
YANDEX_CLIENT_ID=ваш_client_id
YANDEX_DISK_PATH=disk:/Видеовстречи
YANDEX_POLL_SECONDS=10
```

После перезапуска нажмите «Подключить» в разделе Яндекс Диска и войдите на официальной странице Яндекса. Приложение не запрашивает и не хранит пароль. Access/refresh token хранится в каталоге данных с правами `0600` и удаляется кнопкой отключения.

Приложение проверяет только верхний уровень заданной папки каждые 10 секунд. Существующие и новые MP4/WebM попадают в очередь. Неизменённая ревизия повторно не обрабатывается.

## Инструменты для распознавания и конспекта

- **FFmpeg/FFprobe** извлекают аудио из видео WebM/MP4 и проверяют медиафайл.
- **pyannote Community-1** определяет интервалы речи и разделяет спикеров (диаризация).
- **Qwen3-ASR 0.6B (8-bit, MLX)** преобразует речь в текст.
- **Qwen3.5 2B через Ollama** создаёт конспект на основе расшифровки: краткое содержание, решения, задачи и открытые вопросы.

Все модели запускаются локально. Токен Hugging Face нужен только на шаге первоначальной загрузки закрытых весов и не включается в обработку записей.

## Установка

Целевая конфигурация — Apple Silicon M1, 8 ГБ, macOS 15 или новее, Python 3.12 arm64, Node.js 24 LTS и актуальные локальные FFmpeg/FFprobe и Ollama. После установки Ollama и загрузки его модели должно остаться не менее 15 ГБ на томе, где будут храниться речевые модели. Для первоначальной установки нужен интернет и доступ к закрытым файлам. [Community‑1](https://huggingface.co/pyannote/speaker-diarization-community-1)

Установите [Homebrew](https://brew.sh/) и [Ollama для macOS](https://ollama.com/download). Если уже запущено приложение Ollama, завершите его и в отдельном терминале запустите выделенный экземпляр.

```bash
OLLAMA_HOST=127.0.0.1:11434 OLLAMA_NO_CLOUD=1 \
  OLLAMA_NUM_PARALLEL=1 OLLAMA_MAX_LOADED_MODELS=1 ollama serve
```

Из корня проекта в другом терминале выполните следующие команды.

```bash
brew install python@3.12 node@24 ffmpeg git git-lfs
export PATH="$(brew --prefix node@24)/bin:$PATH"
python3.12 -m venv .venv
source .venv/bin/activate

ollama pull qwen3.5:2b --runner llamacpp
python -m pip install -r backend/requirements.lock
npm --prefix frontend ci
npm --prefix frontend run build
cp -n .env.example .env
```

Примите условия Community‑1 и создайте токен чтения с доступом к модели. Передайте его только сценарию подготовки. В интерактивном zsh можно прочитать токен без вывода и записи в историю.
Команда с `--check` проверяет свободное место, наличие токена при необходимости и готовность Ollama без загрузки моделей.

```zsh
read -rs 'meeting_token?Токен Hugging Face: '
printf '\n'
HF_TOKEN="$meeting_token" python scripts/setup_models.py --check
HF_TOKEN="$meeting_token" python scripts/setup_models.py
unset meeting_token

python scripts/check_models.py --offline
bash scripts/start.sh
```

Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000). Для следующего запуска достаточно локального Ollama, активированной `.venv` и `bash scripts/start.sh`. Сценарий запуска поднимает один HTTP-сервер и один исполнитель. Для разработки запустите сервер с `APP_DEV=1 bash scripts/start.sh`, а во втором терминале выполните `npm --prefix frontend run dev`.

`setup_models.py` устанавливает отдельные окружения `.venv-diarize` и `.venv-asr`. Ревизии, хэши публичных файлов и digest модели Ollama закреплены в `scripts/models.lock.json`. Если Ollama показывает другой вариант модели по общему имени, приложение обращается к закреплённому варианту llama.cpp по digest. Для закрытых весов Community‑1 сценарий сверяет SHA‑256 с аутентифицированными метаданными закреплённой ревизии и сохраняет локальный манифест проверки. Офлайн-проверка использует локальный голос macOS либо файл, переданный через `--audio /путь/к/примеру.wav`.

На Mac с уже подготовленным окружением в `~/Library/Application Support/AI Meeting Analyzer` запустите установленный Ollama в отдельном терминале.

```bash
meeting_local="$HOME/Library/Application Support/AI Meeting Analyzer"
OLLAMA_HOST=127.0.0.1:11434 OLLAMA_NO_CLOUD=1 \
  OLLAMA_NUM_PARALLEL=1 OLLAMA_MAX_LOADED_MODELS=1 \
  OLLAMA_MODELS="$meeting_local/models/ollama" \
  "$meeting_local/tools/ollama-v0.40.15/ollama" serve
```

В терминале проекта активируйте окружение командой `source "$HOME/Library/Application Support/AI Meeting Analyzer/envs/app/bin/activate"` и выполните блок с токеном выше. Для отдельной офлайн-проверки добавьте локальные FFmpeg и FFprobe в `PATH` командой `export PATH="$PATH:$HOME/Library/Application Support/AI Meeting Analyzer/tools/bin"`. `start.sh` находит это окружение и инструменты при запуске.

## Данные и качество

База, короткие фрагменты и временные файлы находятся в `~/Library/Application Support/AI Meeting Analyzer/data`, модели — в соседнем каталоге `models`. Такой путь отделяет данные встреч от синхронизируемой папки проекта. `DATA_DIR` и `MODEL_DIR` позволяют выбрать другие локальные каталоги. В работе используются локальные веса, Ollama на loopback и отдельные последовательные процессы для диаризации, WeSpeaker и ASR. Исходники видео и полный WAV удаляются после попытки. Карточки сохраняют короткие фрагменты до решения пользователя. Черновики регистрации голосов истекают через 24 часа. Удаление профиля очищает отпечатки и согласия, сохраняя снимки имён в старых встречах.

Автоимена включаются после успешной калибровки. При заметном сходстве, которого недостаточно для автоназначения, карточка предлагает один или несколько голосовых профилей и просит подтвердить имя. Подсказка доступна и до калибровки, если запись прошла проверку качества. До подтверждения в расшифровке отображается нейтральная метка спикера. В карточках также можно выбрать другой профиль или указать имя только для встречи. Для проверки пригодности голосового образца используются диаризация, минимум 5 секунд полезной речи, уровень RMS от −38 dBFS на 30-мс окнах и максимум 0,5% отсчётов у предела PCM. Уровень и доля клиппинга настраиваются в `.env`. Сильный шум и музыку дополнительно проверяет оператор при прослушивании.

Для калибровки остановите приложение и выполните `python scripts/calibrate.py --manifest acceptance/local/calibration-input.json`. Манифест содержит три непересекающихся по исходным файлам набора. Время указывается в миллисекундах, пути могут быть относительными к манифесту. Идентификаторы людей условные.

```json
{
  "profiles": {
    "p1": [{"file": "enroll-p1.wav", "start_ms": 1000, "end_ms": 13000}]
  },
  "tune": [{
    "file": "tune.mp4",
    "speakers": [
      {"profile": "p1", "intervals": [[1000, 15000]]},
      {"profile": null, "intervals": [[14000, 29000]]}
    ]
  }],
  "validation": [{
    "file": "validation.webm",
    "speakers": [
      {"profile": "p1", "intervals": [[2000, 18000]]},
      {"profile": null, "intervals": [[17000, 35000]]}
    ]
  }]
}
```

Это пример структуры. Для калибровки нужны отдельные размеченные записи с несколькими известными и неизвестными голосами, шумом и наложениями. Скрипт подбирает пороги на `tune` и сохраняет их только при нуле ложных назначений, наличии правильных назначений и отрицательных примеров на независимом `validation`. В отчёте есть количество кластеров, правильных и ложных назначений и доля отказов. Рабочий файл калибровки привязан к ревизии WeSpeaker, предобработке и настройкам качества.

## Проверки

```bash
python -m pip install -r backend/requirements-test.lock
python -m pytest -q
npm --prefix frontend ci
npm --prefix frontend run build
```

Проверено на MacBook Air M1, 8 ГБ, macOS 27.0 (26A428). Сборка прошла на Node.js 24.22.2. Тесты прошли на Python 3.12.16 с FFmpeg 4.4 и FFprobe 4.4.1. Они проверяют фактические контейнеры и границы длительности, а также очередь, API, хранение, конфликт версий, удаление профиля во время сохранения образца и ошибки конспекта. Для тестов очереди и отказов моделей используются подмены адаптеров. Проверен запуск `start.sh` на loopback. В браузере открылись главная страница и диалог профилей. Загруженный через HTTP сгенерированный MP4 дошёл до диаризации и показал ожидаемую ошибку отсутствующего окружения модели.

Для сквозной приёмки сначала выполните `check_models.py --offline`. Затем с отключённым интернетом загрузите разрешённые русскоязычные MP4 и WebM, включая пятиминутную запись. Проверьте покрытие речи и наложения, цитаты четырёх разделов, исправление имени, регистрацию голоса, удаление профиля и восстановление встречи после рестарта. Сопоставьте этапы с выводом исполнителя. Он пишет длительность, пик RSS речевых процессов, наблюдаемый RSS FFmpeg/Ollama и показатели памяти и swap macOS, когда эти данные доступны. В отчёт приёмки также внесите состояние Ollama после генерации и наблюдаемую отзывчивость UI.

На предоставленном WebM длительностью 199,725 секунды и его копии в MP4 длительностью ровно 300 секунд проверены приём файла, очередь, извлечение аудио, очистка временных файлов и восстановление записей о задачах после перезапуска. Чтобы довести MP4 до пяти минут, в конец добавлено начало той же записи.

На этом Mac установлены окружения Python 3.12, FFmpeg и FFprobe, WeSpeaker, Qwen3‑ASR и Ollama 0.40.15 с закреплённой моделью. WeSpeaker вернул 256-мерный вектор на синтетической речи. Qwen3‑ASR распознал 15-секундный отрезок предоставленного WebM за 3,77 секунды. Ollama вернул структурированный конспект на синтетической реплике и выгрузил модель.

Community‑1 установлена, проверка `check_models.py --offline` прошла. Сквозной прогон WebM сохранил 66 реплик, двух спикеров, шесть аудиофрагментов и конспект из четырёх разделов. После перезагрузки приложение возобновило генерацию конспекта из сохранённой расшифровки. Диаризация заняла 282 секунды, распознавание — 23 секунды, генерация после перезапуска — 422 секунды. Пиковый RSS составил около 1,96 ГБ для диаризации и 3,05 ГБ для Ollama. Через API проверена выдача фрагмента в формате WAV по запросу диапазона.

Пятиминутный MP4 сохранил 116 реплик, двух спикеров, шесть аудиофрагментов и конспект из четырёх разделов. Диаризация заняла 340 секунд, распознавание — 30 секунд, повторная генерация конспекта из готовой расшифровки — 88 секунд. Пиковый RSS составил около 3,90 ГБ для диаризации и 3,17 ГБ для Ollama. Приложение ответило на запрос страницы во время диаризации. После обоих прогонов проверено совпадение цитат с исходными репликами и выгрузка модели Ollama.

Смысл конспекта и регистрацию голосов сотрудники проверят в приложении. Пороги автоимён будут определены по фактическим прогонам.
